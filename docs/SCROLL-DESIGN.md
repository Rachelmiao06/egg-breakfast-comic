# 滚动与运动设计（feat/visual-direction，2026-11-14，修订 2）

> **修订 2（用户 2026-11-14）**：①普通前景漫画保持完整静态，不拆手臂、刀、勺、头部，格内循环暂缓；②只有跨景接蛋需要独立蛋、无蛋底图和必要的框线/遮挡层；③故事改为新情节（见第 4 节）；④所有速度倍数和镜头放大倍数都只是**试验参数**，不是标准；不能为了露出蛋把厨房裁得拥挤，也不全程固定成左漫画、右厨房，每段按镜头安排；⑤接缝转场先用 CSS 遮罩做小样验证，不预设能达到 WebGL 参考的效果。

用户方向：温暖、可爱的**分层动画漫画**。滚动时前景漫画、中景灶台、后景厨房以不同速度运动，配合局部动画和声音，像动画镜头一样连续。漫画内容将按本文末尾的清单**重新生成**；本文先定运动和镜头，图按它来画。

## 1. 两个次元，三个接触点

| | 后景：厨房世界 | 前景：妈妈的漫画 |
|---|---|---|
| 质感 | 有空间感的插画，分层，持续自己动 | 平面手绘漫画：纸白、深色墨线、分格、对白 |
| 运动 | 镜头推拉、前中后景错速、环境循环 | 格子进场 / 停留 / 退场；格内只动该动的局部 |
| 时间 | 真实时间（不滚也在动） | 滚动进度（叙事），格内小动作按真实时间循环 |

两者配色协调但**不混成一种画风**。联系只靠三件事：
1. **视线**：妈妈抬眼看向右边时，镜头已经把锅和跳蛋放在画面右侧，她看的就是后景那颗蛋。
2. **声音**：前景动作声（切菜、下锅、搅汁）和后景滋滋声此消彼长。
3. **打破次元**：只有一次——接蛋时，蛋从后景锅里飞出，**越过漫画的框线**，落在妈妈的锅铲上。在此之前，后景的东西从不进入格子，格子里的东西也从不出框。

## 2. 四套运动及其分工（都已有或将有代码落点）

| 系统 | 由什么驱动 | 负责 | 代码落点 |
|---|---|---|---|
| A 环境循环 | 真实时间 | 蛋在锅里跳、火苗、油泡、蒸汽、厨房轻微视差 | `KitchenCharacters`（已修好：不操作 10 秒蛋一直跳） |
| B 滚动镜头 | 统一时间轴 `timeline` | 镜头推拉平移、前中后景错速、场景衔接、漫画格进退场 | `ScrollDriver` → `beats.json`（唯一节奏来源），新增"镜头关键帧 + 景深系数" |
| C 格内动作 | **暂缓** | 普通漫画格保持完整静态；以后若要做，再为个别镜头补分层 | — |
| D 跨景接蛋 | 统一时间轴 | 同一颗蛋从后景锅 → 前景锅铲 → 饭碗 | `Egg`（已有：伸锅铲段落地待命、滚动接管飞行、回滚平滑回锅，全程一颗蛋） |

规则：滚动不替代环境的时间推进；用户停下时厨房仍然活着，前景格子则完全静止、文字清楚。

## 3. 速度设计

### 3.1 层与层之间（同一次滚动，近的动得多）

**以下倍数都是试验起点，按实际观感调，不是标准。** 镜头每移动 1 个单位，各层位移倍数：

| 层 | 倍数 | 说明 |
|---|---|---|
| 漫画格（最近，平面） | 进退场时 1.6–2.0；停留时 0 | 读对白时绝对稳定 |
| 前景物件（桌沿、蛋壳、格纹布） | 1.6 | "桌沿先滑过" |
| 中景（灶台、锅、蛋、火苗） | 1.0 | 镜头推近的主体 |
| 后景（墙、瓷砖、柜子） | 0.35 | "墙只动一点" |

### 3.2 同一元素在故事里的速度变化

每段四个阶段，各配不同曲线，**不统一淡入**：

| 阶段 | 运动 | 曲线 |
|---|---|---|
| 进入 | 从画外滑入，越来越慢 | `power3.out`（减速入场） |
| 动作 | 镜头推近或换景，中速 | `sine.inOut` |
| 停留 | 前景 0 速度；环境照常 | — |
| 退出 | 越来越快地离开 | `power2.in`（加速离场） |

滚动速度（试验）只做一点"跟手"余韵：格子进场时最多 0.8° 的倾角，停下 0.6 秒内回正；阅读时完全静止。不用持续摇晃制造层次。

### 3.3 借鉴 The Boat 的两类触发

- **一次性**：元素到屏幕约 90% 处触发一次进场（约 0.2–0.4 秒、`power4.out`、沿指定方向位移 40–60px），回滚不重播。用于小格子、拟声字、对白气泡弹出。
- **连续映射**：属性随时间轴区间线性映射。用于镜头、景深错速、厨房弱化、**声音音量**（The Boat 的音量也是按滚动区间映射的）。

## 4. 逐段编排（新情节；本轮先验证三种构图）

**新故事**：妈妈取买菜袋，有点累 → 准备配菜饭 → 切菜、炒菜、调汁 → 觉得饭少点什么 → 听见跳蛋 → 伸铲接住 → 放到饭上、淋汁、流黄 → "宝宝，来吃饭啦"。开头**不**决定做荷包蛋；荷包蛋是后来"饭少点什么"时，后景那颗一直在跳的蛋自己送上门。

## 5. 接缝转场（厨房 → 第一格）

参考 SeamTransitions（MIT，Copyright Codrops）：它用 WebGL 着色器，以分层噪声画出毛边接缝，滚动越快羽化越宽，边缘有一圈加深墨线。我们**不复制它的代码**。方向保留，但**先做 CSS 遮罩小样验证**：预先生成一张毛边遮罩图，按第 1 段进入阶段的进度移动 `mask-position`，前沿配一条同形状的墨线图。CSS 遮罩的边缘形状是固定的、不会随速度羽化，**不预设它能达到 WebGL 参考的效果**；小样看过再决定是否保留、改用 Canvas，或放弃。只用这一次。

## 8. 主角层级与读格时间（2026-11-15，修订 3）

问题：格内动画和格外厨房同时抢眼；快滚时格内动画还没播完格子就离场（结尾"拉肚子"那格最明显）。

**一次只有一个主角**：
| 档位 | 谁 | 规则 |
|---|---|---|
| 主角 | 当前阅读的格 / 或接蛋时的蛋 | 同一时刻只有一个 |
| 配角 | 厨房视差、鼠标视差 | 慢、小 |
| 氛围 | 火苗、蒸汽、角色 | 小幅，对比低 |

1. **厨房退后**：v2 节拍表（`beats.visual-v2.json`）里所有有漫画格的段 `kitchenDim` 设为 0.7（组首段从 0.25 渐入、组末段渐出）；蛋是主角的段（drop / prejump / hear / listen / catch）保持 0。`KitchenScene` 的弱化加强为：饱和度 −40%、对比 −20%、盖一层 20% 纸色。不模糊（全屏模糊太贵）。
2. **读格时间下限**：每个有格内动画的段写 `readS`（动画需要的秒数）。`motion.v2.ts` 按从容滚动速度 `BRISK_VH_PER_S = 45` 反推：格子稳定可读的滚动距离 ≥ `readS × 45`，不够就把本段拉长。不吸附、不劫持滚动（之前的磁吸和停留锁已回滚，不再加）。当前：chop 2 s、stirfry 3 s、sauce 2.5 s、punchline 2.2 s。
3. **p6e 提速**：延迟 0.35 s → 0.1 s，逐字 0.19 → 0.15 s/字，蛋黄流动 3.0 s → 2.0 s 内完成。
4. 新增带格内动画的段时，先在节拍表写 `readS`，不要靠到处改代码。

### 8.1 氛围随主角压低（2026-11-15）
`src/lib/calm.ts`：`KitchenScene` 把阅读弱化值写成"安静度"，`Steam`（厨房蒸汽）按 `ambientGain()`（最多 −60%）、`KitchenLayers` 的鼠标与景深视差按 `parallaxGain()`（最多 −50%）每帧读取。炒菜满屏雾（`StirSteam`）移到漫画格下面（z-9，格子 z-10），只罩厨房，不再盖住墨线和对白。

### 8.2 更强的景深视差（2026-11-15）
用户喜欢蛋弹跳段"背景跟着动、像视角在变"，希望全程都有。做法（都是试验值，在 `backgrounds.json` camera 与 `KitchenLayers.tsx` 里调）：
- 镜头关键帧：备菜段（bag→missing）缓慢推近并横移（zoom 1.065→1.115，x 812→884）；饭碗之后（bowl / yolk / eggcall / recognize）也有缓慢推近。格子是 DOM 层不受镜头影响，所以背景在格子后面慢慢"走近"。
- `depthGain` 0.5 → 0.75：远、中、近层错速更明显（弹跳段也更明显）。
- 推近时分层放大（`ZOOM_PARALLAX`：远 0、柜台 0.15、中 0.3、近 0.75）：近的层多长一点，只放大不缩小，不会露边。`calm`（第 8.1 节）会把这部分视差在读格时压低最多 50%。
### 8.3 接蛋格 4:3 被切（已修）
接蛋格进场时镜头还在落（x 902→810），格子被带出屏幕左边约 50px。`ScenePanels` 现在按当前镜头把格子左缘夹在可见范围内；落定后不起作用。`catchView` 也算上了镜头跟蛋的偏移。交接段两格短暂重叠是设计里的"接手"（接蛋格正在滑出、交接格已不透明），属于滑动过程，没有改。

### 8.4 前景纸面倾斜、大格子、结尾"找宝宝"运镜（2026-11-15）
- **纸面倾斜**（`ComicLayer.tsx usePaperTilt`）：整层漫画像一张纸，绕中心做透视旋转，最大 ±1.6°：滚得快时俯仰、镜头横移时偏转、加一点鼠标；弹簧平滑，停手回正，阅读时静止。用 CSS 3D，不用着色器（成本低，效果够）。
- **大格子**：横屏下单格宽度上限 66vw（饭碗大横幅原来 85vw）；静态格随滚动在停留阶段慢慢推近 1 → 1.035（可逆）。
- **结尾运镜**（`backgrounds.json` camera 关键帧）：search 先看左边再扫向右边（找宝宝），eggcall 推近朝蛋叫声的方向（zoom 1.16），return 拉回，recognize 慢推近，worry / punchline 回稳。镜头横移越大，纸面偏转和背景错速越明显，所以滚动、镜头、格子三者是串在一起的。数值都是试验值。

### 8.5 甩出距离上限与宽屏重叠（2026-11-15）
- **甩出距离上限**（`ScrollDriver.tsx` 的 Lenis `virtualScroll`）：已排队等着滚的距离超过上限时，同方向的新滚轮增量不再累加。平时 100vh，读带格内动画的格子（节拍表有 `readS`、处于进入/停留阶段）时 45vh。反向永远放行。用 40 个连续滚轮增量测试：不加上限约 388vh（1400×990 窗口），现在约 107vh。不是吸附也不是劫持。
- **宽屏两格重叠**：`fitPlaces` 窗口比 16:10 窄时整组放大，原来只放大宽度、y 不动，格子变高就压到下一格。现在 y 也绕本组中心同比例放大。1400×990 下扫了备菜段（240–1300vh），没有重叠和被切。
- p5e"回头"表演需要新图，见 `docs/ASSET-REQUESTS-p5e-turn.md`。

### 8.6 读格门：格内动画不能跳过（2026-11-15，用户明确要求）
`src/lib/scroll-gate.ts` + `ScrollDriver` + `PanelPerf.useStage(…, gateS)`：带格内动画的格子开始表演时"拦住"滚动，动画播完才放行。
- 门的位置 = 当前段"停留"结束处（格子开始离场之前）；到了门口，向前的滚轮增量被吞掉，已经被甩过门的（惯性 / 触屏）用 0.6 s 缓出温柔拉回门口。往回滚永远放行，回去会收住表演并放开门。
- 时长（秒，+0.4 兜底超时，不会卡死）：hear 2.4、切菜 2.6、炒菜 3.2、调汁 2.8、p6e 2.2。减少动态效果 / `?perf=0` 时不拦。新增带动画的格子时在 `useStage` 的最后一个参数写秒数。
- 实测（1024×768）：炒菜格停留中连续 25 个滚轮增量，停在 974vh（门口）；动画播完后再滚可继续。
- 这就是之前回滚掉的"停留锁"的更克制版本：不改格子的位置和淡出，只限制故事往前走；用户想改就调秒数或把 `gateS` 设 0。

### 8.7 去掉"漂浮"、整体放慢（2026-11-15）
- **关掉纸面倾斜和推近**：用户觉得"每次滑一下，格子都先漂一下，不真实"。`usePaperTilt` 现在传 `false`（代码保留，`TILT` 常量还在，想再试可改回 `!reducedMotion`），格内静态图的滚动推近也关了。格子现在是钉在屏幕上的纸，只在进入 / 退出时动。背景的视差和镜头运动保留。
- **整体放慢**：`motion.v2.ts` 的 `LEN_SCALE = 1.35`（每段滚动距离 ×1.35，页面总长约 3800vh → 5100vh）；Lenis `wheelMultiplier` 0.8 → 0.55、`duration` 1.25 → 1.5 s；一次甩出上限 80vh（读格动画时 40vh）。实测 10 个滚轮增量在读格段只走 40vh。

### 8.12 滚动和动画联动：表演时锁住位置、有先后的格子排队（2026-11-15，用户）
- **表演开始就锁住滚动位置**（`ScrollDriver` 的 `lockPx`）：表演一开始，把当时的位置锁住（给 4vh 余地），向前的滚动被吞掉，已经冲过的惯性 0.6 s 缓出拉回。原来只是"拦在这一段停留结束处"，动画还在画的时候人还能继续往前滚；现在动画和滚动是一回事，动画画完才放行。往回滚永远放行（会收住表演）。
- **表演排队**（`scroll-gate.ts requestTurn`）：同一时刻只有一个格子在表演。想开始的格子先问"轮到我了吗"：别的格子还在播，或同段里 `order` 更小的格子还在等，就每 120 ms 再问一次；轮到之后才播并锁滚动。所以有前后顺序的两格（例如 p5d 之后的 p5e）一个播完才播下一个，不会同时在画。`useStage` 的第 8 个参数 `seq` = 格子的 `order`。
