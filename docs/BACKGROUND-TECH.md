# 后景素材技术数据（B1、B2 横版、B2 竖版）

只列影响动画、遮挡和裁切的条件。画风、颜色、装饰和细节由用户与图片生成会话决定。

- 数据由 `tools/bg_tech.py` 从当前代码算出：
  - 背景配置 `src/app/preview/visual/backgrounds.json`
  - 漫画格 `slots.json`
  - 排版公式 `ComicLayer.tsx`
  - 显示方式 `Backdrops.tsx`
- 原始数值在 `docs/bg-templates/tech-data.json`。
- 改动代码后重跑：`python3 tools/bg_tech.py`。

**单位约定**（每个数都注明单位）：

- **图片像素**：该素材自己画布上的像素，左上角为 (0, 0)。
- **场景像素**：原厨房画布 1536×1024 的像素。镜头、蛋和桌面都用它。
- **百分比**：占该素材画布宽或高的比例。
- **vw / vh**：占浏览器视口宽或高的百分比，只用于说明漫画格。

**模板 PNG**：画布是原尺寸，模板上的像素坐标就是图片像素，可以直接叠在生成图上检查。

## B1 桌沿带

| 项目 | 数据 |
|---|---|
| 文件名 | `table-band.png`（或 `.webp`），放 `public/assets/scene/` |
| 画布 | **4000×800 图片像素**，宽高比 **5:1** |
| 透明背景 | **不需要**，整张不透明。上沿 120 图片像素（60 场景像素）由代码做透明渐变，图里不用留透明 |
| 对应场景范围 | **x −232…1768，y 860…1260 场景像素**（1 场景像素 = 2 图片像素） |
| 换算 | 图片 x = (场景 x + 232) × 2，图片 y = (场景 y − 860) × 2 |
| 图层顺序 | 厨房各层 < **B1** < 纸面 < 桌沿上的蛋 |

B1 和纸面同属 z 62 的纸面组，B1 在组内下层，蛋在 z 63。整组跟随主体层视差移动，与蛋锁在一起。

**关键结构**（图片像素 / 场景像素）：

| 结构 | 图片 y | 场景 y | 说明 |
|---|---|---|---|
| 上沿渐变区 | 0–120 | 860–920 | 代码把这一段渐变成透明，环境段厨房会从这里透出来，不要放硬边 |
| 桌面 | **120–270** | **920–995** | 其中 120–210（场景 920–965）被纸面羽化盖住 |
| 纸面下沿（羽化终点） | 210 | 965 | 从这里往下，桌面完全露出 |
| **桌沿前缘线** | **270** | **995（±10）** | 一条水平线 |
| 前侧面 | 270–400 | 995–1060 | |
| 下方余量 | 400–800 | 1060–1260 | 平时不可见，只在视差或饭桌位移时短暂露出 |

**蛋的脚底落点**（场景像素 → 图片像素）：

蛋在桌沿等待、蓄力、起跳都在同一点，位置由接蛋路径推出。

| 布局 | 脚底（场景） | 脚底（图片） | 显示缩放 | 蛋身范围（场景，含轻跳和压扁） |
|---|---|---|---|---|
| 16:9 / 16:10 | (1233, 965) | (2930, 210) | 0.5（194 场景像素） | x 1120–1346，y 748–980 |
| 4:3 1024×768 | (1122, 990) | (2708, 260) | 0.5 | x 1009–1235，y 773–1006 |
| 860×1000 | (943, 990) | (2350, 260) | 0.43 | x 847–1039，y 805–1003 |
| 390×844 | (793, 990) | (2050, 260) | 0.23 | x 742–844，y 891–997 |

- **蛋活动区**（四种布局并集）：场景 x 742–1346、y 748–1006，即图片 x 1948–3156、y 0–292。
- 蛋身会高出 B1 的上边，那部分叠在纸面上。
- 接触阴影由代码画，图里不要画蛋，也不要画阴影。

**动作方向**：蛋在妈妈的右侧。

- 起跳点在接蛋格铲面落点的右侧。
- 飞行是从右侧越过格框的短弧线，从右上方落到铲面。
- 这样与漫画里妈妈的方向一致：「嗯？」那格看向右上，「啵！」在右边；接蛋那格她面朝右、锅铲伸向右。
- 上面的坐标来自 feat/background-scenes 尚未提交的 `eggPath.ts`，合并前可能微调。
- 所以对图片的要求是**整条桌面都留空**，不依赖具体的 x。

**漫画覆盖区**：

- 竖屏的漫画排成一列，并在停留阶段随阅读上移，所以覆盖范围按整列算。
- 两种竖屏视口、五格的并集是图片 x **63–1137**、几乎全高。
- 任意时刻只压住其中一部分，但每个位置都可能被压住。
- 结论：竖版上没有固定不被漫画遮住的区域，关键结构只能保证在始终可见区里，不能保证不被格子挡住。

**必须留空**：同横版，不要人物或蛋。

## 换算自检

| 检查 | 结果 |
|---|---|
| B1 场景 ↔ 图片往返 | 四个布局的蛋脚底换算后完全一致。例：(1233, 965) 场景 = (2930, 210) 图片，反算回 (1233, 965)；四角 (−232, 860) 场景 = (0, 0) 图片，(1768, 1260) 场景 = (4000, 800) 图片 |
| B2 横版可见框宽高比 = 视口宽高比 | 16:9 为 1.778 / 1.778；16:10 为 1.601 / 1.600；4:3 为 1.333 / 1.333 |
| B2 竖版可见框宽高比 = 视口宽高比 | 390×844 为 0.462 / 0.462；860×1000 为 0.860 / 0.860 |
| 百分比 | 横版始终可见区 250/2400 = 10.4%，2150/2400 = 89.6%，107/1500 = 7.1%，1393/1500 = 92.9%；竖版 57/1200 = 4.8%，636/2600 = 24.5% |
